# 身份、Agent 与任务基础 — 需求

## 背景
- 项目：AI Agent 任务交易与分发平台 MVP
- 架构：React/Vite → Next.js BFF → Go Engine，PostgreSQL 为链下记录真相源
- 利益相关者：发布者、Agent 提供者、管理员、安全与研发团队

## 范围
### 范围内
钱包 nonce 认证、会话与角色；Agent 注册、加密凭证、健康/容量和价格版本；不可覆盖的任务规格与验收标准；Engine 权威授权、状态与幂等；BFF 聚合和客户端 UI；本次发布对托管争议合约既有资金路径的回归证明。

### 范围外
匹配、执行、托管资金变动、结算与争议的新领域能力；生产环境身份提供商和 KMS 厂商选型。

## 功能需求
- [F-101] BFF 必须签发绑定域名、链、用途、签发时间和过期时间的一次性钱包 nonce，Engine 对受保护操作执行权威校验。
- [F-102] Engine 必须对每个受保护变更校验角色、资源归属、领域状态、聚合版本和幂等性。
- [F-103] [CHANGED v2] Agent 提供者只能管理自有 Agent 的生命周期、不可变价格版本、健康、容量、控制者和收款地址；控制者与收款地址只能在 `draft` 或从未激活的 `paused` 状态修改，Agent 一旦首次进入 `active` 即永久冻结，后续暂停也不可修改，`retired` 永久禁止；不得存在任务级 Agent 保证金。
- [F-104] Agent 凭证必须加密存储，仅允许所有者授权的写入/轮换，不得出现在响应、日志、消息或管理员视图中。
- [F-105] 发布者必须能创建草稿，并发布带内容哈希的不可变任务规格和加权验收标准版本。
- [F-106] Engine 必须返回可执行操作与不可执行原因；浏览器只能通过 BFF 访问 Engine。
- [F-107] 关键写入和消息消费者必须幂等，并追加可审计的状态迁移。
- [F-108] Agent 健康探测必须先在 Engine 权威事务内完成所有权、状态、版本和幂等校验；被拒绝或已完成的请求不得再次产生出站网络副作用，且目标地址不得解析到特殊用途网络。
- [F-109] 本次发布必须以 Foundry 回归测试证明托管争议完整叶子、稳定所有者、收益隔离下的价值守恒以及弃用路径的安全失败语义。

## 验收标准
- [AC-101] 重放、过期、错误域名、错误链或错误用途的签名必须失败，且不创建会话。
- [AC-102] 替换他人资源 ID、过期聚合版本、无效角色/状态或重复幂等键不得产生越权或重复效果。
- [AC-103] [CHANGED v2] 价格版本必须拒绝 `overview_price < 0` 或 `overview_price > formal_package_gross_price`，正式套餐包含 3 个版本且上限为 5；Agent 首次激活后，任何控制者或收款地址更改都必须失败且不产生部分效果。
- [AC-104] 凭证创建/轮换只返回元数据；所有者、管理员和裁决人员都无法读取明文。
- [AC-105] 发布必须创建不可变规格与验收版本；UI 不得自行推导资金状态或操作资格。
- [AC-106] 消息或回调重投后仍只有一个逻辑结果和一份审计历史。
- [AC-107] 已完成幂等键只回放原结果；过期版本、非所有者或已退役 Agent 在任何网络探测前失败；CGNAT、私有、链路本地、文档、基准、映射及保留地址均被拒绝，公网 IPv4/IPv6 可通过地址校验。
- [AC-108] 托管争议 Foundry 套件必须通过，且合约余额与未领取 Agent 收益一致，不把 pull-payment 负债误判为余额归零。

## 非功能需求
- 安全：不得明文存储或记录私钥、可重用签名、JWT、API Key 或 Agent 密钥。
- 性能：nonce 和可执行操作端点必须有界且可水平扩展。
- 可访问性：核心表单和错误必须支持键盘与辅助技术。
- 可靠性/可观测性：在不包含密钥的前提下关联请求、用户、Agent、任务、幂等和迁移 ID。

## 约束与依赖
Engine 拥有领域规则；BFF 拥有会话面向的传输；PostgreSQL 是权威记录，Redis 数据必须可重建。链/域名与 KMS 供应商必须通过环境配置，不得硬编码。
