# 匹配、概览与 Agent 选择 — 需求

## 背景
- 项目：AI Agent 任务交易与分发平台 MVP
- 架构：Engine 拥有确定性匹配与调度规则，BFF/Web 负责呈现
- 利益相关者：发布者、Agent 提供者、排序、风控与财务团队

## 范围
### 范围内
硬过滤、三路召回、评分、有界模型调整、FairShuffle、快照审计、受限概览执行、校验、补位和原子 Agent 选择。
### 范围外
正式交付与最终结算。

## 功能需求
- [F-201] Engine 必须依次执行硬过滤、三路召回、去重、100 分规则评分、有界模型调整、合格筛选与确定性 FairShuffle。
- [F-202] 合格池必须同时满足两项分数不低于 60，且与最高分差不超过 10；最多保留 20 个、返回 3 个，默认每服务商 1 个，15% 探索仅可占第三位。
- [F-203] 相同任务/修订/算法版本的刷新结果必须稳定，并持久化可解释快照、排除原因、权重、概率、位置和 seed 摘要。
- [F-204] 最多 3 个概览执行必须共用截止时间，使用脱敏简报、只读工具、独立 allocation、逻辑执行身份和客观校验。
- [F-205] 仅有有效概览可结算；允许一次确定性补位；过时修订不得选择；重试不得重复执行或计费。
- [F-206] 选择必须校验当前概览、健康/容量、发布者授权和平台证明，再原子消费 nonce、创建唯一 assignment、应用一次抵扣、锁定正式净应付并释放超额资金。

## 验收标准
- [AC-201] 依赖降级时不合格 Agent 仍不得通过；合格 Agent 不足 3 个时返回实际数量。
- [AC-202] 相同输入必须复现排名与候选；有效输入变化必须增加修订号并保留新旧快照。
- [AC-203] 概览 Worker 不得使用外部写工具、超过成本上限或暴露未脱敏输入。
- [AC-204] 超时、无效输出、重试、重投与补位对每个 allocation 最多产生一个可付结果。
- [AC-205] 并发、重放、过期、跨链、篡改或交叉拼接的选择最多产生一个 assignment，且不重复抵扣。

## 非功能需求
- 安全：使用短期限域令牌和签名回调，不泄露密钥或完整任务。
- 性能：每路召回 Top-100，最多评分 100 个，最多并行 3 个概览。
- 可访问性：比较页必须以语义化方式展示解释与操作拒绝原因。
- 可靠性/可观测性：降级、评分、补位和 allocation 结果必须可审计。

## 约束与依赖
依赖 T-103 和 T-105。Qdrant/模型/Redis 故障必须使用固定降级策略，不得绕过门槛。托管选择执行依赖功能 4 的合约决策与任务。
