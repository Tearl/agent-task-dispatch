# SQ 经验记录

- 链、资产、费率、治理和保留期等不可逆决策，必须依赖经版本化确认的产品基线，不得由实现隐式决定。
- 即使 BFF 或 UI 已校验，Engine 仍必须作为授权与幂等的最终权威。
- 依赖 PostgreSQL 事务级 advisory lock 后读取新提交结果的并发协议，应显式固定 `READ COMMITTED`，并在更高会话默认隔离级别下验证等待者的幂等性。
- 公开 nonce 签发应复用活跃 challenge，用钱包级锁与分片原子限流桶实现跨副本边界；限流协调数据可清理，但不得为此删除不可变的 nonce 历史。
- 健康与租约等时效判断必须使用取得领域锁后的数据库时钟；调用方时间戳只能在有界偏差内作为观测值，不能决定权威新鲜度。
- 容量缓存必须在读写边界按未过期租约派生或对账；预留与释放应统一“聚合后租约”的锁顺序，并按 reservation ID 串行化首次幂等请求。
- 发布不可变版本时，聚合更新、领域/审计事件和去重 Outbox 必须在同一事务中提交。
- 凭证持久化接口应在类型层面拒绝明文，只接收 envelope ciphertext、wrapped DEK 与非敏感元数据；确定性幂等摘要也应在进入仓储前清除。
- 凭证 KEK 与幂等 HMAC 密钥必须独立管理，使 KEK 轮换不破坏历史请求的稳定回放；本地启动文档必须提供安全、可执行的密钥生成步骤。
- 截止时间等时变业务校验必须在幂等记录未命中后、事务内使用数据库时钟执行；否则已成功请求在时间边界后的重投会丢失稳定回放语义。
- 聚合资源与可执行操作时，应由 Engine 在同一数据库快照中返回资源、聚合版本和 decision；并用完整状态迁移图校验 action 清单，避免合法迁移不可发现或跨请求混合快照。
