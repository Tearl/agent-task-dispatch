# 托管、账本、结算与退款 — 需求

## 背景
- 项目：AI Agent 任务交易与分发平台 MVP
- 架构：Solidity 合约是资金真相源，PostgreSQL 保存不可变复式记账镜像
- 利益相关者：发布者、Agent 提供者、财务、合约安全与运营团队

## 范围
### 范围内
四个隔离业务子账、allocation、复式分录、链上同步、选择/工作/验收资金路径、退款、收益、提现与对账。
### 范围外
策略决策批准前不实现生产生息适配器；争议分配属于功能 5。

## 功能需求
- [F-401] `DiscoveryPool`、`FormalEscrow`、`ChangeOrderEscrow` 和 `DisputeFeePool` 必须拥有独立 ID、余额、权益归属、状态、退款规则和不可变流水；外部成本使用隔离 allocation。
- [F-402] 每个 journal 必须借贷平衡且只能冲正；所有写入、事件和消费者必须幂等。
- [F-403] 合约必须校验调用者、资产、账户、金额、nonce、证明、链与状态，原子执行选择并防止重入/重放。
- [F-404] 验收必须释放判给 Agent 的正式金额；已结算有效概览费、无关收入和 Agent 收益不得追索；V1 提前验收不退未用套餐轮次。
- [F-405] 退款必须遵循生命周期和责任，不得向发布者收取重复失败/平台故障成本，不得通过后续争议追回终态本金。
- [F-406] Agent 收益只能由本人提现，仅在明确选择后进入生息；每日对账比较合约、金库、账本和应收。
- [F-407] 链上消费者必须持久化交易/区块/日志/确认状态，并幂等处理重放、乱序和重组。

## 验收标准
- [AC-401] 跨账支出、allocation 复用、不平分录、原位更正和重复消费必须失败。
- [AC-402] 选择、抵扣、净额锁定、超额释放、work nonce、验收、退款和提现在并发/重放下保持价值守恒。
- [AC-403] 正式退款/争议路径无法触及有效概览费与其他任务收益。
- [AC-404] 链重组、重放与乱序必须收敛到权威资金状态，不产生重复账本效果。
- [AC-405] 日对账必须检测所有注入差异，并记录告警与审计处置。

## 非功能需求
- 安全：检查—生效—交互、重入保护、限域角色、暂停/多签准备与属性测试。
- 可靠性/可观测性：链上是资金真相，差异必须告警并进入对账。
- 性能：支持安全批处理，不得弱化单账户不变量。

## 约束与依赖
阶段 0 的链、资产、精度、费率、子账架构、签名、角色和多签决策是生产合约语义的门槛。测试可用明确的本地默认值，但不得作为生产默认值发布。
