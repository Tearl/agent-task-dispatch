# 正式交付与变更单 — 需求

## 背景
- 项目：AI Agent 任务交易与分发平台 MVP
- 架构：Engine 拥有版本/状态权威，并与托管合约 work nonce 协同
- 利益相关者：发布者、Agent 提供者、财务与运营团队

## 范围
### 范围内
正式 V1–V3、结构化修改、交付证明、验收意图/确认、冻结范围、责任与已注资 V4/V5 变更单。
### 范围外
争议裁决与生息策略实现。

## 功能需求
- [F-301] Engine 必须事务性分配 V1–V3，每套餐最多一个活动生成；重试、回调或内容重复不得增加版本或重复计费。
- [F-302] 修订必须绑定上一有效版本、合并结构化反馈、聚合版本、范围、work nonce、证明和 Agent 响应。
- [F-303] 只有链上确认可记录验收确认；新工作开始前必须消费新的已授权 work nonce，并使旧结算资格失效。
- [F-304] 冻结范围必须覆盖规格、选中概览、输入、验收标准、输出约束、工具、成本上限和排除项。
- [F-305] V4/V5 必须依赖包含范围差异、责任、资金来源、本金/余额归属、价格和截止时间的生效变更单；V6 永久拒绝。
- [F-306] Agent 责任工作不得要求 Agent 入金，不得扣押钱包、既有收益或其他任务收入；平台责任未判给 Agent 的余额默认返回事故账户。

## 验收标准
- [AC-301] 并发启动、重试、分片、重复回调与相同结果只创建一个版本和计费结果。
- [AC-302] V2/V3 缺少有效前版本、反馈或 work nonce 时不得开始；过时版本不得结算。
- [AC-303] UI 必须区分验收意图、待链上确认与已确认验收。
- [AC-304] 未注资、未接受或责任待决的变更单不得执行；各类有效责任必须保持资金边界。
- [AC-305] 对同一交付单元/套餐/范围修订，V6 在重试或变更单完成后仍必须失败。

## 非功能需求
- 安全：证明和 nonce 必须绑定所有适用的领域与链字段。
- 可靠性/可观测性：每个版本、尝试、反馈、责任和状态迁移必须只追加且可追溯。
- 可访问性：版本差异和操作必须支持键盘与辅助技术。

## 约束与依赖
依赖 assignment T-205、执行 T-203 和托管工作/结算接口 T-403/T-404。
